Domain 01 Portability Assessment OSFI requires FRFIs to formally assess portability at onboarding, at renewal, and upon material change for all cloud arrangements.
Req ID B-10 Requirement B-10 Ref Priority Status Current State / Evidence Gap / Action Required Owner Target Date
P-01 Portability considered at onboardingCloud portability formally assessed before entering any new CSP arrangement S4.2 Critical
P-02 Portability reassessed at renewalPortability re-evaluated at each contract renewal or material change event S4.2 Critical
P-03 Benefits and risks of portability documentedFormal assessment documents both upside and downside of portability for each arrangement S4.2 High
P-04 Portability tiering / criticality classificationCloud arrangements classified by risk and criticality with portability requirements scaled accordingly S2.1 Critical
Domain 02 Concentration Risk Management B-10 requires FRFIs to identify and manage both institution-specific and systemic CSP concentration risk, including 4th-party and geographic dimensions.
Req ID B-10 Requirement B-10 Ref Priority Status Current State / Evidence Gap / Action Required Owner Target Date
C-01 Institution-specific concentration assessedOver-reliance on a single CSP for multiple critical functions is identified and managed S2.3.3 Critical
C-02 Systemic concentration assessedAwareness and reporting on sector-wide CSP dependency where the same provider serves multiple FRFIs S2.3.3 High
C-03 Geographic concentration assessedRisk of single-region dependency within a CSP identified and managed with appropriate regional failover S2.3.3 High
C-04 4th-party / subcontractor concentration mappedCSP subcontractors identified and common dependencies across providers assessed S2.3.4 High
C-05 Concentration risk KRIs defined and monitoredQuantitative risk indicators with breach thresholds approved at Board / senior management level S2.3.3 High
Domain 03 Technical Portability Controls Architecture and engineering controls that enable genuine workload and data portability across cloud providers.
Req ID B-10 Requirement B-10 Ref Priority Status Current State / Evidence Gap / Action Required Owner Target Date
T-01 Multi-cloud or secondary environment capabilityStrategy (e.g. active-passive, active-active) in place to mitigate single CSP dependency for critical workloads S4.2 Critical
T-02 Workload containerization and IaC standardsCritical workloads containerized and deployable via Infrastructure-as-Code on an alternate provider S4.2 High
T-03 Open data formats for critical data assetsPersistent data stored in provider-neutral formats (e.g. Parquet, Avro) — not proprietary CSP-native formats S4.2 High
T-04 API abstraction over CSP-native servicesApplication code decoupled from provider-specific APIs via abstraction layer or cloud-agnostic SDK S4.2 High
T-05 BYOK encryption with FRFI-controlled key custodyData encrypted with keys held by the FRFI — not delegated to the CSP key management service S3.2 High
T-06 Data sovereignty — Canadian residency enforcedPolicy-as-Code or equivalent control prevents workloads and data landing outside approved Canadian regions S3.1 Critical
Domain 04 Exit Strategy & Continuity Planning B-10 requires credible, tested exit strategies for high-risk and critical arrangements — covering both planned and stressed exit scenarios.
Req ID B-10 Requirement B-10 Ref Priority Status Current State / Evidence Gap / Action Required Owner Target Date
E-01 Exit strategy documented for critical arrangementsFormal exit plan covering planned and stressed scenarios exists for all Tier 1 / critical cloud arrangements S2.3.5 Critical
E-02 Board-approved exit triggers definedSpecific, measurable thresholds that automatically invoke the exit plan are approved at Board level S2.3.5 Critical
E-03 RTO and RPO targets defined for CSP failoverBoard-approved recovery time and recovery point objectives for each critical cloud arrangement S2.3.5 Critical
E-04 Portability / failover exercises conductedAnnual exercises simulating primary CSP failure and validating failover within approved RTO/RPO targets S2.3.5 Critical
E-05 Migration runbooks documented and maintainedStep-by-step operational runbooks for CSP migration exist, are version-controlled, and assigned to a named owner S2.3.5 High
